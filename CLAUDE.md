## What this repo is

Meridian is a travel planning web app (Next.js + Neon PostgreSQL). The repo is currently in the **database/backend setup phase** — the application layer (Next.js app, UI, API routes) does not exist yet. Only the database schema, Drizzle config, and CI/CD migration pipeline are in place.

## Database commands

```bash
npm run db:generate   # Generate a migration from schema changes
npm run db:migrate    # Apply pending migrations (requires DATABASE_URL)
npm run db:studio     # Open Drizzle Studio in the browser
npm run db:push       # Push schema directly to DB, skipping migration files (dev only)
```

## Local setup

Copy `.env.example` to `.env.local` and fill in `DATABASE_URL` with a connection string from the [Neon Console](https://console.neon.tech) (staging branch is safe for local dev).

## Architecture

### Database layer (`src/db/`)

- `schema.ts` — Drizzle table definitions. All tables cascade-delete from `trips`.
- `index.ts` — exports a single `db` client using `@neondatabase/serverless` (HTTP driver, not WebSocket) connected via `DATABASE_URL`.
- Import the client as `import { db } from "@/db"` (or relative path until path aliases are configured).

### Schema overview

```
trips (userId, name, destination, dates, archived)
├── itinerary_items (date, time, title, location, sortOrder)
├── expenses (category, amount, currency, date)
└── packing_items (name, category, packed, sortOrder)
```

### Migrations (`drizzle/`)

Migration files are append-only SQL generated by `drizzle-kit`. **Never edit an existing migration** — add a new one instead.

### CI/CD (`.github/workflows/migrate.yml`)

- PR opened → migrations run against `STAGING_DATABASE_URL` (Neon `staging` branch)
- Merged to `main` → migrations run against `PRODUCTION_DATABASE_URL` (Neon `production` branch)

Both secrets must be set in **GitHub → Settings → Secrets and variables → Actions**.

## Making schema changes

1. Edit `src/db/schema.ts`
2. Run `npm run db:generate` — commits the new file in `drizzle/`
3. Open a PR — CI applies the migration to staging automatically
